# Day 07 — Linux Storage Management: Partitions and Filesystems

## Цель дня

Углубить знания об устройстве дисковой подсистемы Linux, изучить схемы разметки дисков GPT и MBR, научиться анализировать таблицы разделов, исследовать параметры файловых систем ext4 и проверять их целостность.

## Изученные темы

### 1. Схемы разметки дисков: MBR и GPT

- MBR (Master Boot Record) — устаревшая схема разметки дисков.
- GPT (GUID Partition Table) — современная схема разметки дисков.
- `sudo fdisk -l` — просмотр таблиц разделов и характеристик дисков.
- `sudo parted /dev/sda print` — просмотр подробной информации о разделах диска.
- `sudo sgdisk -p /dev/sda` — просмотр структуры GPT.

Изучены основные различия:

- MBR использует 32-битную адресацию секторов и при стандартном размере сектора 512 байт ограничен примерно 2 TiB.
- MBR поддерживает до четырёх основных разделов; расширенные и логические разделы позволяют обходить это ограничение.
- GPT использует GUID для идентификации диска и разделов.
- GPT хранит основную и резервную копии таблицы разделов.
- Типичная конфигурация GPT предусматривает до 128 записей разделов.

Разобраны понятия:

- Таблица разделов.
- Основной и резервный заголовки GPT.
- GUID диска.
- Тип раздела.
- Начальный и конечный секторы.
- Выравнивание разделов по границам 1 MiB.
- Свободное пространство между разделами.

### 2. Анализ таблицы разделов

- `sudo fdisk -l /dev/sda` — просмотр информации о диске и его разделах.
- `sudo parted /dev/sda print` — просмотр разделов, файловых систем и флагов.
- `sudo sgdisk -p /dev/sda` — просмотр параметров GPT и идентификаторов разделов.

Изучены:

- Номер раздела.
- Начальный и конечный секторы.
- Размер раздела.
- Тип раздела.
- Флаги GPT.
- Коды типов разделов.

Рассмотрены примеры кодов GPT:

- `EF00` — EFI System Partition.
- `0C01` — Microsoft Reserved.
- `0700` — Microsoft Basic Data.
- `2700` — Windows Recovery Environment.
- `8300` — Linux filesystem.
- `8200` — Linux swap.

Важно: код типа раздела не определяет фактическую файловую систему. Например, тип `8300` сам по себе не означает, что внутри раздела обязательно находится ext4.

### 3. UUID, PARTUUID и метки

- `sudo blkid` — просмотр типов файловых систем, UUID и меток.
- `lsblk -f` — просмотр файловых систем и их идентификаторов.
- `sudo sgdisk -p /dev/sda` — просмотр GUID диска и сведений о GPT.

Изучены различия:

- UUID — уникальный идентификатор файловой системы.
- PARTUUID — уникальный идентификатор раздела в таблице GPT.
- LABEL — метка файловой системы.
- PARTLABEL — имя раздела в таблице разделов.

Рассмотрено применение UUID и PARTUUID для идентификации устройств независимо от имён `/dev/sdX`.

### 4. Изучение параметров ext4 с помощью tune2fs

- `sudo tune2fs -l /dev/sda5` — просмотр параметров файловой системы ext4.
- `sudo tune2fs -l /dev/loop0` — просмотр параметров ext4 на тестовом loop-устройстве.
- `grep -E` — фильтрация нужных строк вывода по нескольким шаблонам.

Изучены параметры:

- Filesystem state — состояние файловой системы.
- Filesystem UUID — идентификатор файловой системы.
- Block count — общее количество блоков.
- Free blocks — количество свободных блоков.
- Reserved block count — количество зарезервированных блоков.
- Block size — размер блока.
- Inode count — общее количество inode.
- Free inodes — количество свободных inode.
- Filesystem features — поддерживаемые возможности файловой системы.
- Mount count — количество монтирований.
- Maximum mount count — порог количества монтирований для проверки.
- Check interval — интервал автоматической проверки.

Разобраны особенности ext4:

- Journaling — журналирование операций файловой системы.
- Extents — способ организации диапазонов блоков.
- Directory indexing — индексирование каталогов.
- Metadata checksums — контрольные суммы метаданных.
- Reserved blocks — резервирование части пространства, обычно для привилегированного пользователя root.

### 5. Проверка файловых систем с помощью e2fsck

- `sudo e2fsck -f /dev/loop0` — принудительная проверка файловой системы.
- `sudo e2fsck -n /dev/loop0` — проверка без внесения изменений.
- `sudo e2fsck -fn /dev/loop0` — принудительная проверка без исправления обнаруженных ошибок.

Изучены пять основных этапов проверки ext-файловой системы:

1. Проверка inode, блоков и размеров.
2. Проверка структуры каталогов.
3. Проверка связности каталогов.
4. Проверка счётчиков ссылок.
5. Проверка сводной информации о группах блоков.

Важно: проверку и исправление файловой системы необходимо выполнять на размонтированном разделе. Для проверки корневой файловой системы может потребоваться Live-система или recovery-окружение.

### 6. Работа с loop-устройствами

Повторно использован файловый образ, созданный в Day 06.

- `sudo losetup --find --show` — подключение файла к свободному loop-устройству.
- `sudo losetup -l` — просмотр активных loop-привязок.
- `lsblk -f` — просмотр файловых систем на блочных устройствах.
- `findmnt` — проверка состояния монтирования.
- `sudo losetup --detach` — отключение loop-устройства.

Изучена последовательность безопасной проверки файловой системы на тестовом блочном устройстве.

## Практическая лабораторная работа

Выполнено исследование таблицы разделов реального диска Kali Linux и проверка файловой системы ext4 внутри тестового файла-образа.

### 1. Исследование диска и схемы разметки

С помощью `sudo fdisk -l /dev/sda` определены характеристики основного диска:

- Устройство: `/dev/sda`.
- Модель: Micron_1100_MTFD.
- Размер: 476.94 GiB.
- Размер сектора: 512 байт.
- Схема разметки: GPT.

С помощью `parted` изучены разделы и их флаги.

Определены разделы:

- `/dev/sda1` — EFI System Partition, FAT32, 100 MiB.
- `/dev/sda2` — Microsoft Reserved, 16 MiB.
- `/dev/sda3` — Microsoft Basic Data, NTFS.
- `/dev/sda4` — Windows Recovery Environment, NTFS, 521 MiB.
- `/dev/sda5` — Linux filesystem, ext4, корневая файловая система Kali Linux.
- `/dev/sda6` — Linux swap.

Обнаружено предупреждение `fdisk` о том, что записи разделов расположены не по порядку. Проверка через `parted` показала, что номера разделов не соответствуют их физическому порядку расположения на диске.

### 2. Исследование GPT

Командой `sudo sgdisk -p /dev/sda` изучены параметры таблицы GPT.

Получены следующие сведения:

- GUID диска: `FF386DD3-555D-40F2-8F46-E7C0E3F97325`.
- Максимальное количество записей разделов: 128.
- Основная таблица разделов: секторы 2–33.
- Первый доступный сектор: 34.
- Последний доступный сектор: 1000215182.
- Выравнивание разделов: 2048 секторов, что соответствует 1 MiB при размере сектора 512 байт.

Изучены коды типов разделов и их назначение.

### 3. Исследование UUID и PARTUUID

С помощью `blkid` изучены идентификаторы файловых систем и разделов.

Для корневого раздела `/dev/sda5` получены:

- Тип файловой системы: ext4.
- UUID: `84d1b762-2ca0-4537-a028-3badccbb0dd3`.
- PARTUUID: `9a5bac97-bccd-49bf-8baa-0521650589eb`.
- PARTLABEL: `KALI`.

Также исследованы идентификаторы EFI, NTFS и swap-разделов.

### 4. Исследование параметров корневой файловой системы

Командой `sudo tune2fs -l /dev/sda5` изучены параметры реальной корневой файловой системы ext4.

Получены основные показатели:

- Состояние файловой системы: `clean`.
- Размер блока: 4096 байт.
- Всего блоков: 25349888.
- Свободно блоков: 17229539.
- Зарезервировано блоков: 1267494.
- Всего inode: 6340608.
- Свободно inode: 5613127.

Изучены поддерживаемые функции ext4, журналирование, резервирование блоков, счётчики монтирования и параметры автоматической проверки.

Команда использовалась только для чтения параметров. Реальная файловая система не изменялась.

### 5. Подключение тестового файлового образа

Повторно подключён файл-образ, созданный в Day 06:

`day06-disk-filesystems/lab/disk.img`

Командой `sudo losetup --find --show` получено устройство `/dev/loop0`.

Проверено:

- Файловая система: ext4.
- Размер образа: 100 MiB.
- UUID: `9dff5fc9-b13f-4dd3-a0c9-047e5246ba5c`.
- Файловая система не смонтирована.

### 6. Проверка файловой системы с помощью e2fsck

Выполнена команда:

`sudo e2fsck -fn /dev/loop0`

Проверка прошла все пять этапов:

- Проверка inode, блоков и размеров.
- Проверка структуры каталогов.
- Проверка связности каталогов.
- Проверка счётчиков ссылок.
- Проверка сводной информации о группах блоков.

Ошибок файловой системы не обнаружено.

Итоговые показатели:

- Всего inode: 25584.
- Использовано inode: 14.
- Свободно inode: 25570.
- Всего блоков: 102400.
- Использовано блоков: 12114.
- Свободно блоков: 90286.
- Размер блока: 1024 байта.

Параметры дополнительно проверены командой:

`sudo tune2fs -l /dev/loop0`

Подтверждено состояние файловой системы `clean`.

### 7. Проверка и отключение loop-устройства

Проверены параметры тестовой файловой системы и количество свободных блоков и inode.

Затем loop-устройство отключено:

`sudo losetup --detach /dev/loop0`

Командой `sudo losetup -l` подтверждено отсутствие активных loop-привязок.

Командой `lsblk -f` проверено состояние блочных устройств: `/dev/loop0` отсутствует, реальные разделы диска остались без изменений.
