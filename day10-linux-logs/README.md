# Day 10 — Linux Logs and Diagnostics

## Цель дня

Изучить систему журналирования Linux, научиться просматривать и анализировать системные журналы, сообщения ядра и состояние служб.

Дополнительно изучить базовые инструменты сетевой диагностики Linux и механизм ротации журналов с помощью `logrotate`.

## Изученные темы

### 1. Системный журнал journald

- Назначение `systemd-journald` и просмотр системного журнала через `journalctl`.
- Фильтрация записей по приоритету с помощью `-p`.
- Просмотр журналов конкретной службы через `-u`.
- Фильтрация записей по временному диапазону с помощью `--since` и `--until`.
- Просмотр журналов текущей и предыдущей загрузки через `-b` и `-b -1`.
- Просмотр списка сохранённых загрузок через `--list-boots`.
- Просмотр подробных полей записи через `-o verbose`.
- Уровни приоритета journald.

### 2. Файловые системные журналы

- Изучение структуры каталога `/var/log`.
- Просмотр журнала dpkg через `/var/log/dpkg.log`.
- Анализ истории операций APT через `/var/log/apt/history.log`.
- Просмотр подробного вывода операций APT через `/var/log/apt/term.log`.
- Разница между историей операций APT и журналом действий dpkg.

### 3. Диагностика ядра Linux

- Просмотр сообщений ядра через `dmesg`.
- Фильтрация сообщений ядра через `journalctl -k`.
- Просмотр предупреждений и ошибок ядра.
- Разница между временем загрузки в `dmesg` и календарными метками в `journalctl`.
- Анализ сообщений ядра с учётом их источника и контекста.

### 4. Диагностика systemd и служб

- Проверка служб в состоянии `failed` через `systemctl --failed`.
- Просмотр состояния конкретной службы через `systemctl status`.
- Анализ журнала отдельной службы через `journalctl -u`.
- Разница между состояниями `active`, `inactive`, `failed`, `enabled` и `disabled`.
- Анализ записей с учётом приоритета и контекста.

### 5. Основы сетевой диагностики Linux

- Просмотр сетевых интерфейсов и IP-адресов через `ip`.
- Просмотр таблицы маршрутизации через `ip route`.
- Изучение TCP- и UDP-сокетов через `ss`.
- Просмотр прослушиваемых портов и активных соединений.
- Разница между TCP- и UDP-сокетами на уровне диагностики.
- Проверка состояния SSH-службы через `systemctl` и `journalctl`.
- Изучение конфигурации SSH-сервера и эффективных параметров через `sshd -T`.
- Разница между установленным SSH-сервером, его конфигурацией, состоянием службы и прослушиваемым портом.
- Первичная проверка сетевой доступности узлов через `ping`.

### 6. Ротация журналов с помощью logrotate

- Назначение `logrotate` и необходимость ротации журналов.
- Изучение глобальной конфигурации `/etc/logrotate.conf`.
- Изучение дополнительных конфигураций в `/etc/logrotate.d/`.
- Директивы `daily`, `rotate`, `compress`, `missingok`, `notifempty` и `create`.
- Настройка пользователя и группы через директиву `su`.
- Проверка конфигурации в режиме отладки через `-d`.
- Принудительная ротация через `-f`.
- Использование отдельного файла состояния через `-s`.
- Запуск ротации с помощью systemd timer и service.

## Практическая работа

### 1. Анализ системных журналов

- Просмотрены последние записи системного журнала через `journalctl`.
- Изучена фильтрация по приоритетам, службе и времени.
- Сравнены записи текущей и предыдущей загрузки.
- Просмотрены подробные поля отдельных записей.
- Проанализированы журналы службы `cron`.

### 2. Анализ файловых журналов

- Изучено содержимое `/var/log`.
- Просмотрена история установки пакетов в `dpkg.log`.
- Проанализированы операции APT в `apt/history.log`.
- Изучен подробный вывод операций APT в `apt/term.log`.
- Сопоставлены записи APT и dpkg.

### 3. Диагностика ядра и systemd

- Просмотрены сообщения ядра через `dmesg` и `journalctl -k`.
- Изучены предупреждения и ошибки ядра.
- Проверено состояние служб через `systemctl --failed`.
- Проанализированы сообщения журналов с учётом источника, приоритета и контекста.
- Изучено состояние `logrotate.service` и его связь с `logrotate.timer`.

### 4. Основы сетевой диагностики

- Проверены сетевые интерфейсы и IP-адреса через `ip -br addr`.
- Изучена таблица маршрутизации через `ip route`.
- Просмотрены TCP- и UDP-сокеты через `ss`.
- Проверены прослушиваемые порты и активные соединения.
- Изучено состояние SSH-службы.
- Проверены конфигурация SSH-сервера и эффективные параметры `sshd -T`.
- Сопоставлены настройки SSH-сервера, состояние службы и наличие слушающего порта.
- Выполнена проверка доступности шлюза через `ping`.

### 5. Практика с logrotate

- Созданы тестовый лог `app.log` и конфигурация `logrotate.conf`.
- Настроены ежедневная ротация, хранение трёх архивов и сжатие.
- Разобрана необходимость безопасных прав доступа к конфигурации и директивы `su`.
- Выполнена проверка конфигурации через `logrotate -d`.
- Использован отдельный файл состояния `/tmp/logrotate-lab.status`.
- Выполнена принудительная ротация через `logrotate -f`.
- Проверено создание нового `app.log`.
- Проверено содержимое сжатого архива через `zcat`.
