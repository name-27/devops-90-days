# Journalctl Practice

## 1. Просмотр журналов

- `journalctl` — просмотр системного журнала.
- `journalctl -n 20` — последние 20 записей.
- `journalctl -b` — записи текущей загрузки.
- `journalctl -b -1` — записи предыдущей загрузки.

## 2. Фильтрация по приоритету

- `journalctl -p err` — ошибки и более высокие приоритеты.
- `journalctl -p warning` — предупреждения и более высокие приоритеты.
- `journalctl -p err -b` — ошибки текущей загрузки.

Приоритеты journald:

- `0` — emerg
- `1` — alert
- `2` — crit
- `3` — err
- `4` — warning
- `5` — notice
- `6` — info
- `7` — debug

## 3. Фильтрация по времени и службе

- `journalctl --since "30 minutes ago"` — записи за последние 30 минут.
- `journalctl --since today` — записи с начала текущего дня.
- `journalctl -u cron.service` — записи службы cron.
- `journalctl -u cron.service -p err` — ошибки и более высокие приоритеты службы cron.

## 4. Форматирование и подробности

- `journalctl -o verbose -n 1` — подробные поля записи.
- `journalctl --list-boots` — список загрузок, сохранённых в журнале.
- `journalctl -k` — сообщения ядра.

## 5. Практические правила

- Сначала определить временной диапазон и источник сообщения.
- Проверить приоритет, службу и контекст записи.
- Повторяющиеся сообщения не обязательно означают неисправность.
- Приоритет err сам по себе не доказывает критическую проблему.
- Сопоставлять сообщения журнала с реальным поведением системы.
