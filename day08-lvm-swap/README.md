# Day 08 — Linux Storage: LVM, Swap and Persistent Mounts

## Цель дня

Изучить управление логическими томами Linux с помощью LVM, научиться создавать и расширять логические тома, работать с Swap-файлами и настраивать автоматическое подключение файловых систем через `/etc/fstab`.

## Изученные темы

### 1. LVM (Logical Volume Manager)

- LVM — система управления дисковым пространством, позволяющая объединять несколько физических устройств или разделов в единый пул хранения и создавать логические тома.
- Основные компоненты LVM:
  - **PV (Physical Volume)** — физический том, подготовленное для использования в LVM устройство или раздел.
  - **VG (Volume Group)** — группа томов, объединяющая один или несколько PV.
  - **LV (Logical Volume)** — логический том, создаваемый внутри VG.
- Связь компонентов: PV объединяются в VG, внутри которой создаются LV.
- Logical Volume можно расширять за счёт свободного пространства Volume Group.
- После расширения LV файловую систему необходимо увеличить отдельно.

### 2. Установка и проверка LVM

- Установка пакета `lvm2` с помощью пакетного менеджера APT.
- Проверка наличия команды `lvm`.
- Основные команды:
  - `sudo apt update`
  - `sudo apt install lvm2`
  - `which lvm`
  - `lvm version`

### 3. Loop devices и тестовые диски

- Loop device позволяет использовать обычный файл в качестве блочного устройства.
- Это удобно для создания безопасных лабораторных стендов без изменения реальных дисков и разделов.
- Создание файлов-образов с помощью `fallocate`.
- Подключение файлов-образов к loop-устройствам.
- Основные команды:
  - `fallocate -l`
  - `losetup --find --show`
  - `losetup -l`
  - `losetup --detach`
  - `lsblk`

### 4. Управление LVM

- Создание физических томов:
  - `pvcreate`
  - `pvs`
  - `pvdisplay`
- Создание группы томов:
  - `vgcreate`
  - `vgs`
  - `vgdisplay`
- Создание логического тома:
  - `lvcreate`
  - `lvs`
  - `lvdisplay`
- Расширение логического тома:
  - `lvextend`
- Проверка распределения пространства между физическими устройствами:
  - `sudo lvs -o lv_name,vg_name,lv_size,seg_count,devices`
  - `sudo pvs -o pv_name,pv_size,pv_used,pv_free`

### 5. Файловая система и расширение LV

- Создание файловой системы ext4 на логическом томе с помощью `mkfs.ext4`.
- Подключение файловой системы через `mount`.
- Проверка источника и параметров монтирования с помощью `findmnt`.
- Расширение файловой системы после увеличения логического тома с помощью `resize2fs`.
- Проверка доступного пространства с помощью `df -hT`.
- Разница между размером логического тома и размером файловой системы.

### 6. Swap

- Swap — пространство на диске, которое Linux может использовать в качестве дополнительной виртуальной памяти.
- Swap может располагаться на отдельном разделе или в файле.
- Создание Swap-файла с помощью `fallocate`.
- Настройка прав доступа к Swap-файлу.
- Создание Swap-области с помощью `mkswap`.
- Активация и деактивация Swap:
  - `swapon`
  - `swapoff`
- Настройка приоритета Swap с помощью параметра `-p`.
- Проверка активных Swap-областей:
  - `swapon --show`
  - `free -h`
- Проверка типа файла и его параметров с помощью `file`.

### 7. Файл /etc/fstab и постоянное монтирование

- `/etc/fstab` содержит настройки файловых систем и Swap, которые система использует при загрузке.
- Основные поля записи:
  1. Устройство или UUID.
  2. Точка монтирования.
  3. Тип файловой системы.
  4. Параметры монтирования.
  5. Параметр dump.
  6. Порядок проверки файловой системы.
- Использование UUID вместо нестабильных имён устройств.
- Настройка автоматического подключения ext4 и Swap.
- Проверка конфигурации через альтернативный файл с помощью:
  - `mount -a -T`
  - `swapon --all --fstab`
  - `findmnt`
  - `swapon --show`

## Практическая лабораторная работа

### 1. Установка LVM

Установлен пакет `lvm2`, необходимый для работы с Logical Volume Manager.

Выполнены команды:

- `sudo apt update`
- `sudo apt install lvm2`
- `which lvm`

Проверено наличие исполняемого файла:

- `/usr/sbin/lvm`

### 2. Создание тестовых дисков

Для лабораторной работы созданы два файла-образа размером 200 MiB каждый.

Команды:

- `fallocate -l 200M disk1.img`
- `fallocate -l 200M disk2.img`

Файлы подключены к loop-устройствам:

- `disk1.img` → `/dev/loop0`
- `disk2.img` → `/dev/loop1`

Проверено подключение с помощью `losetup -l` и `lsblk`.

Таким образом, были получены два тестовых блочных устройства без изменения реального диска системы.

### 3. Создание PV и VG

На двух loop-устройствах созданы физические тома:

- `sudo pvcreate /dev/loop0`
- `sudo pvcreate /dev/loop1`

Проверено состояние PV с помощью `sudo pvs` и `sudo pvdisplay`.

Затем создана группа томов:

- `sudo vgcreate vg_devops /dev/loop0 /dev/loop1`

Результат:

- Имя VG: `vg_devops`
- Количество PV: 2
- Общий размер VG: 392 MiB
- Размер Physical Extent (PE): 4 MiB
- Количество extents: 98
- Свободное пространство после создания VG: 392 MiB

Размер VG оказался меньше суммарного размера файлов-образов, поскольку часть пространства не используется LVM под данные PV.

### 4. Создание Logical Volume

Внутри `vg_devops` создан логический том:

- `sudo lvcreate -L 150M -n lv_data vg_devops`

Запрошенный размер составлял 150 MiB, но LVM округлил его до 152 MiB.

Причина: размер Logical Volume выделяется блоками Physical Extent размером 4 MiB. Для 150 MiB потребовалось 38 extents, что соответствует 152 MiB.

Результат:

- VG: `vg_devops`
- LV: `lv_data`
- Фактический размер LV: 152 MiB
- Количество выделенных extents: 38

Проверено с помощью `sudo lvs`, `sudo vgs` и `sudo pvs`.

### 5. Создание файловой системы и монтирование LV

На логическом томе создана файловая система ext4:

- `sudo mkfs.ext4 /dev/vg_devops/lv_data`

UUID файловой системы:

`640b44a0-3029-4aa1-822c-c144d33cb0b0`

Создан каталог для монтирования:

- `mkdir -p day08-lvm-swap/lab/mnt/data`

Логический том подключён:

- `sudo mount /dev/vg_devops/lv_data day08-lvm-swap/lab/mnt/data`

Проверено с помощью `findmnt` и `df -hT`.

Корневой каталог смонтированной файловой системы передан текущему пользователю:

- `sudo chown name:name day08-lvm-swap/lab/mnt/data`

Внутри файловой системы созданы тестовые данные:

- `test.txt` — 17 байт, содержимое `LVM storage test`.
- `projects/info.txt` — 20 байт, содержимое `DevOps learning lab`.

Проверены права доступа, владельцы и структура каталогов.

### 6. Расширение Logical Volume

Выполнено расширение логического тома на 50 MiB:

- `sudo lvextend -L +50M /dev/vg_devops/lv_data`

Из-за размера Physical Extent в 4 MiB LVM округлил запрошенное увеличение до 52 MiB.

Новый размер LV:

- До расширения: 152 MiB.
- Добавлено: 52 MiB.
- После расширения: 204 MiB.

Важно: увеличение LV само по себе не увеличивает файловую систему ext4.

Поэтому отдельно выполнено расширение файловой системы:

- `sudo resize2fs /dev/vg_devops/lv_data`

После операции проверено новое доступное пространство с помощью `df -hT`.

Размер файловой системы увеличился примерно со 137 MiB до 186 MiB.

### 7. Проверка распределения пространства между PV

С помощью команды:

- `sudo lvs -o lv_name,vg_name,lv_size,seg_count,devices`

Проверено, что логический том использует оба физических тома.

Результат:

- `lv_data` — 204 MiB.
- Количество сегментов: 2.
- Используются `/dev/loop0` и `/dev/loop1`.

Дополнительно выполнена проверка:

- `sudo pvs -o pv_name,pv_size,pv_used,pv_free`

Результаты:

| PV | Размер | Использовано | Свободно |
|---|---:|---:|---:|
| `/dev/loop0` | 196 MiB | 196 MiB | 0 MiB |
| `/dev/loop1` | 196 MiB | 8 MiB | 188 MiB |

Итоговое состояние VG:

- Размер: 392 MiB.
- Использовано под LV: 204 MiB.
- Свободно: 188 MiB.

Таким образом, на практике проверено, что один Logical Volume может использовать пространство нескольких Physical Volume внутри одной Volume Group.

### 8. Создание и настройка Swap-файла

В лабораторном каталоге создан Swap-файл размером 64 MiB:

- `fallocate -l 64M swapfile`

Настроены владелец и права доступа:

- `sudo chown root:root swapfile`
- `sudo chmod 600 swapfile`

Создана Swap-область:

- `sudo mkswap swapfile`

UUID Swap-файла:

`039aa1b1-40e1-4eaa-aad5-33b82dbd4606`

Swap-файл активирован:

- `sudo swapon swapfile`

Затем проверена настройка приоритета.

Сначала Swap отключён, после чего повторно активирован с приоритетом 10:

- `sudo swapoff swapfile`
- `sudo swapon -p 10 swapfile`

Результат `sudo swapon --show`:

| Swap-устройство | Размер | Приоритет |
|---|---:|---:|
| `/dev/sda6` | 977 MiB | -1 |
| `swapfile` | 64 MiB | 10 |

В системе уже существовал Swap-раздел `/dev/sda6`. Он не изменялся.

Проверено, что новый Swap-файл активен и имеет более высокий приоритет.

### 9. Проверка постоянного монтирования через fstab

Для проверки автоматического подключения создана отдельная тестовая копия системного файла `/etc/fstab`:

- `sudo cp /etc/fstab fstab.test`

В тестовый файл добавлены две записи.

Запись для ext4:

`UUID=640b44a0-3029-4aa1-822c-c144d33cb0b0 /home/name/devops-90-days/day08-lvm-swap/lab/mnt/data ext4 defaults 0 2`

Запись для Swap:

`/home/name/devops-90-days/day08-lvm-swap/lab/swapfile none swap defaults,pri=10 0 0`

Для проверки сначала выполнено отключение тестовых ресурсов:

- файловая система ext4 размонтирована;
- Swap-файл отключён.

Затем проверено подключение через тестовый файл:

- `sudo mount -a -T fstab.test`
- `sudo swapon --all --fstab fstab.test`

Результат проверен с помощью:

- `findmnt`
- `sudo swapon --show`

Подтверждено, что файловая система ext4 подключается к указанному каталогу, а Swap-файл активируется с заданным приоритетом.

**Важно:** настоящий `/etc/fstab` не изменялся. Проверка выполнялась исключительно через отдельный файл `fstab.test`. Перезагрузка системы для проверки не выполнялась.
