# Day 06 — Linux Disk and Filesystem Management

## Цель дня

Изучить устройство дисков и разделов Linux, научиться определять типы файловых систем, анализировать использование дискового пространства и inode, искать файлы по различным критериям, а также освоить создание и подключение файловых систем.

## Изученные темы

### 1. Просмотр дисков и разделов

- `lsblk` — просмотр блочных устройств и их структуры.
- `lsblk -f` — просмотр файловых систем, UUID и точек монтирования.
- `sudo fdisk -l` — просмотр информации о дисках и таблицах разделов.
- `sudo blkid` — определение типов файловых систем, UUID и меток устройств.
- `findmnt` — просмотр смонтированных файловых систем.
- `findmnt /` — определение файловой системы корневого каталога.
- `findmnt -t` — фильтрация файловых систем по типу.
- `findmnt -o SOURCE,TARGET,FSTYPE` — вывод выбранных параметров монтирования.

Изучены основные характеристики блочных устройств:

- Диски и разделы.
- Типы файловых систем: ext4, NTFS, FAT32, swap.
- UUID и метки файловых систем.
- Точки монтирования.
- Различия между физическими и виртуальными файловыми системами.

### 2. Анализ использования дискового пространства

- `df -h` — просмотр использования дискового пространства в удобном формате.
- `df -h /` — проверка свободного пространства корневой файловой системы.
- `df -i` — просмотр использования inode.
- `df -i /` — проверка inode корневой файловой системы.
- `du -sh` — получение общего размера каталога.
- `du -h --max-depth=1` — просмотр размеров вложенных каталогов.
- `sort -h` — сортировка размеров с учётом единиц измерения.

Изучены показатели:

- Size — общий размер файловой системы.
- Used — занятое пространство.
- Avail — доступное пространство.
- Use% — процент использования.
- Inodes — количество файловых объектов, которые может обслуживать файловая система.

Разобраны различия между логическим размером файла и фактически занимаемым пространством на диске.

### 3. Поиск файлов и каталогов

- `find` — поиск файлов и каталогов.
- `-type f` — поиск обычных файлов.
- `-type d` — поиск каталогов.
- `-type l` — поиск символических ссылок.
- `-name` — поиск по имени с учётом регистра.
- `-iname` — поиск по имени без учёта регистра.
- `-size` — поиск по размеру.
- `-empty` — поиск пустых файлов и каталогов.
- `-readable` — поиск доступных для чтения объектов.
- `-writable` — поиск доступных для записи объектов.
- `-mtime` — фильтрация по времени изменения в днях.
- `-mmin` — фильтрация по времени изменения в минутах.
- `-xdev` — ограничение поиска текущей файловой системой.
- `-path` — фильтрация по пути.
- `-prune` — исключение каталогов из дальнейшего обхода.
- `-print` — вывод найденных объектов.

Практически проверены:

- Поиск файлов по расширению и имени.
- Поиск файлов определённого размера.
- Поиск пустых файлов и каталогов.
- Поиск файлов по времени изменения.
- Подсчёт количества файлов и каталогов.
- Исключение `.git` из поиска с помощью `-prune`.

### 4. Определение типа файлов и работа с inode

- `file` — определение типа содержимого файла.
- `stat` — просмотр подробной информации о файле.
- `ls -lh` — просмотр логического размера файла.
- `du -h` — просмотр фактически занимаемого пространства.

Изучены:

- Inode — структура файловой системы, содержащая метаданные файла.
- Номер inode.
- Права доступа и владелец файла.
- Размер и количество выделенных блоков.
- Время доступа, изменения содержимого и метаданных.

### 5. Работа с loop-устройствами

- `modinfo loop` — просмотр информации о модуле loop.
- `lsmod` — просмотр загруженных модулей ядра.
- `sudo modprobe loop` — загрузка модуля loop.
- `ls -l /dev/loop*` — просмотр loop-устройств.
- `losetup` — управление loop-устройствами.
- `sudo losetup --find --show` — поиск свободного loop-устройства и подключение файла.
- `sudo losetup -l` — просмотр активных loop-привязок.
- `sudo losetup --detach` — отсоединение loop-устройства.

Изучено назначение loop-устройств: они позволяют использовать обычный файл в качестве блочного устройства.

### 6. Создание и подключение файловой системы

- `dd` — создание файлового образа.
- `mkfs.ext4` — создание файловой системы ext4.
- `mount` — подключение файловой системы к каталогу.
- `umount` — безопасное отключение файловой системы.
- `df -h` — проверка использования пространства смонтированной файловой системы.
- `findmnt` — проверка точки монтирования.
- `stat` — просмотр метаданных тестового файла.

Изучены:

- Создание файлового образа.
- Подключение образа через loop-устройство.
- Форматирование устройства в ext4.
- Создание точки монтирования.
- Подключение и отключение файловой системы.
- Различия между размонтированием файловой системы и отсоединением loop-устройства.

## Практическая лабораторная работа

Выполнено исследование дисковой подсистемы Kali Linux и создание отдельной файловой системы ext4 внутри файла-образа.

### 1. Анализ дисковой подсистемы

С помощью `lsblk`, `lsblk -f`, `blkid`, `fdisk` и `findmnt` изучена структура дисков и разделов.

Определены:

- Основной диск `/dev/sda`.
- Корневой раздел `/dev/sda5` с файловой системой ext4.
- EFI-раздел `/dev/sda1` с файловой системой FAT32.
- Разделы `/dev/sda3` и `/dev/sda4` с файловой системой NTFS.
- Раздел swap `/dev/sda6`.

Проверено использование дискового пространства и inode с помощью `df`.

### 2. Анализ каталогов и файлов

Исследовано использование дискового пространства домашнего каталога и репозитория DevOps.

С помощью `du` определены размеры каталогов и отдельных директорий.

С помощью `find` выполнен поиск:

- Файлов по имени и расширению.
- Файлов по размеру.
- Пустых файлов и каталогов.
- Файлов по времени изменения.
- Обычных файлов, каталогов и символических ссылок.
- Файлов, доступных для чтения и записи.

Проверено исключение каталога `.git` из поиска.

Подсчитано количество объектов в репозитории:

- 182 обычных файла.
- 113 каталогов.

### 3. Создание файлового образа

Создан каталог лабораторной работы:

`day06-disk-filesystems/lab/`

Создан файл-образ размером 100 MiB:

`day06-disk-filesystems/lab/disk.img`

Использована команда:

`dd if=/dev/zero of=day06-disk-filesystems/lab/disk.img bs=1M count=100 status=progress`

Первоначально файл содержал нулевые данные и определялся командой `file` как `data`.

### 4. Подключение loop-устройства

Загружен модуль ядра `loop` с помощью `modprobe`.

Файл-образ подключён к свободному loop-устройству:

`sudo losetup --find --show day06-disk-filesystems/lab/disk.img`

Получено устройство `/dev/loop0`.

Проверена связь между файлом и блочным устройством с помощью `losetup -l`.

### 5. Создание файловой системы ext4

На устройстве `/dev/loop0` создана файловая система ext4:

`sudo mkfs.ext4 /dev/loop0`

Получен UUID:

`9dff5fc9-b13f-4dd3-a0c9-047e5246ba5c`

Проверены тип файловой системы и UUID с помощью `lsblk -f` и `blkid`.

### 6. Монтирование и работа с файлами

Создан каталог для монтирования:

`day06-disk-filesystems/lab/mnt`

Файловая система подключена:

`sudo mount /dev/loop0 day06-disk-filesystems/lab/mnt`

Проверено подключение через `findmnt` и использование пространства через `df -h`.

Внутри файловой системы созданы:

- `test.txt` — тестовый пустой файл.
- `test-dir` — тестовый каталог.

Изучены права доступа, владельцы и служебный каталог `lost+found`.

С помощью `stat` проверены метаданные тестового файла, включая inode, размер, права доступа и владельца.

### 7. Безопасное отключение

Файловая система отключена:

`sudo umount day06-disk-filesystems/lab/mnt`

Проверено отсутствие точки монтирования через `findmnt`.

Loop-устройство отсоединено:

`sudo losetup --detach /dev/loop0`

Повторная проверка `losetup -l` подтвердила отсутствие активных loop-привязок.

С помощью `lsblk -f` проверено состояние блочных устройств.

Команда `file` подтвердила, что файл `disk.img` содержит файловую систему ext4.
