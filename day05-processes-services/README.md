# Day 05 — Linux Processes and Services

## Цель дня

Изучить управление процессами Linux, научиться отслеживать использование системных ресурсов, управлять приоритетами процессов, проверять состояние системных служб и анализировать системные журналы.

## Изученные темы

### 1. Просмотр и анализ процессов

- `ps` — просмотр процессов.
- `ps aux` — просмотр запущенных процессов с подробной информацией.
- `ps -ef` — полный список процессов.
- `ps -ef --forest` — отображение дерева процессов.
- `ps -p PID -o ...` — просмотр выбранных параметров конкретного процесса.
- PID — идентификатор процесса.
- PPID — идентификатор родительского процесса.
- STAT — состояние процесса.
- TTY — управляющий терминал.
- VSZ — виртуальная память.
- RSS — физическая память, используемая процессом.
- Kernel threads — потоки ядра Linux.

### 2. Поиск и управление процессами

- `pgrep` — поиск процессов по имени.
- `pgrep -a` — вывод PID и командной строки.
- `pgrep -c` — подсчёт найденных процессов.
- `pgrep -x` — точное совпадение имени процесса.
- `kill` — отправка сигналов процессам.
- `kill -TERM` — запрос на корректное завершение процесса.
- `kill -KILL` — принудительное завершение процесса.
- `kill -STOP` — приостановка процесса.
- `kill -CONT` — продолжение выполнения процесса.
- `kill -l` — просмотр списка сигналов.
- `jobs` — просмотр фоновых заданий текущей оболочки.
- `&` — запуск команды в фоновом режиме.
- `$!` — PID последнего процесса, запущенного в фоне.

### 3. Приоритеты процессов

- `nice` — запуск процесса с заданным значением nice.
- `renice` — изменение приоритета уже работающего процесса.
- NI — значение nice.
- PRI — приоритет планировщика.
- Диапазон nice: от -20 до 19.
- Чем выше значение nice, тем ниже относительный приоритет процесса при распределении CPU.

Практически проверены запуск процессов с разными значениями nice и изменение приоритета с помощью renice.

### 4. Мониторинг системных ресурсов

- `top` — мониторинг процессов и системных ресурсов в реальном времени.
- `top -b -n 1` — однократный вывод информации в пакетном режиме.
- `free -h` — использование оперативной памяти и swap.
- `uptime` — время работы системы и load average.
- `nproc` — количество доступных логических CPU.
- `lscpu` — информация о процессоре.

Изучены показатели:

- CPU: user, system, idle, iowait и другие.
- Load average за 1, 5 и 15 минут.
- RAM: total, used, free, buff/cache, available.
- Swap: общий объём и использование.

### 5. Управление системными службами

- `systemctl` — управление службами systemd.
- `systemctl status` — просмотр состояния службы.
- `systemctl start` — запуск службы.
- `systemctl stop` — остановка службы.
- `systemctl restart` — перезапуск службы.
- `systemctl enable` — настройка автозапуска.
- `systemctl disable` — отключение автозапуска.
- `systemctl is-active` — проверка текущего состояния.
- `systemctl is-enabled` — проверка настройки автозапуска.
- `systemctl list-units` — просмотр загруженных units.
- `systemctl list-unit-files` — просмотр установленных unit-файлов.
- `systemctl daemon-reload` — перечитывание конфигурации systemd.
- `systemctl cat` — просмотр содержимого unit-файла.
- `systemd-analyze verify` — проверка unit-файла.

Изучены состояния служб:

- `active`, `inactive`, `failed`.
- `enabled`, `disabled`, `static`, `masked`.
- Различия между текущим состоянием службы и настройкой автозапуска.

### 6. Создание тестовой systemd-службы

В качестве тестовой команды использовался:

`/usr/bin/sleep infinity`

Проверены:

- Проверка unit-файла с помощью `systemd-analyze verify`.
- Перечитывание конфигурации через `daemon-reload`.
- Запуск и остановка службы.
- Перезапуск службы.
- Проверка состояния через `systemctl status`.
- Включение и отключение автозапуска.
- Просмотр конфигурации через `systemctl cat`.

После завершения практики тестовая служба остановлена, unit-файл удалён, конфигурация systemd обновлена.

### 7. Работа с системными журналами

- `journalctl` — просмотр системных журналов.
- `journalctl -n 10` — последние 10 записей.
- `journalctl -b` — журналы текущей загрузки.
- `journalctl -u SERVICE` — журналы выбранной службы.
- `journalctl -f` — просмотр новых записей в реальном времени.
- `journalctl --since` — фильтрация по времени.
- `journalctl -p err` — сообщения уровня error и выше.
- `journalctl -p warning` — сообщения уровня warning и выше.
- `--no-pager` — вывод без интерактивного просмотрщика.

Изучены уровни приоритета сообщений журнала и особенности анализа системных предупреждений и ошибок.
